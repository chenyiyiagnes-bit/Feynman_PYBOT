# omega_mind

一个围绕 **PyBot** 的规则型“右脑”状态层：26 个事件评估器 → 7 维情绪状态 → 风格指令 → 台词。
没有训练，没有权重，纯 Python 标准库。

## 运行

```bash
cd ~/Desktop/量子模拟/右脑
python3 -m omega_mind --persona generic
python3 -m omega_mind --persona feynman --verbose
```

命令：`/state` 看状态，`/save` 存档，`/reset` 重置，`/challenge` 进入教回挑战，`/exit` 退出；
`/cube` 看魔方，`/turn U` 手动转一面（`R'`、`F2` 也认），`/memory` 看三层记忆，
`/relations` 看关系图，`/dream` 立即整理一次。挑战模式里直接打字回答，`/next` 换一题，
`/stop` 退出挑战。默认存档 `mind_state.json`（在启动目录）。

```bash
python3 -m omega_mind --lang en         # 英文模式（也可以进 CLI 后 /lang en）
python3 -m omega_mind --serve 8765      # HTTP + WebSocket + 仪表盘 /，WS /ws
python3 -m omega_mind --profile         # 语料画像后退出
```

### 中文 / 英文两个模式

- 启动时 `--lang zh|en`，运行时 `/lang zh`、`/lang en`（`/zh`、`/en` 也行），服务器 `POST /api/lang`，
  WebSocket 消息里带 `{"lang": "en"}`。
- 模式是**全局**的：整轮对话只用一种语言，不会中英混排。
- 中文模式：左脑是费曼卡片 + 内置库，**不调用 PyBot**（它只会英文）。
- 英文模式：左脑是同一批卡片的**英文译文层**（`data/kb_en/*.jsonl`，按 `id` 覆盖回复字段），
  没命中卡片才落到 PyBot 或英文内置库；中文原文始终是事实源，译文层不改上游语料。
  原本就是英文的网页引文（`verified_facts`）保持原样，不做中文回译。
  译文是**翻译**，不是费曼原话；要引用原话时只用 `verified_facts` 或原始英文片段。
- 语言不匹配的回复一律换成对应语言的兜底句。
- 渲染器的前缀/语气词分语言两套，历史也分开记，切换模式不会串。
- 语言选择会随存档保存。

服务器接口：`GET /api/state|cube|memory|relations|dreams|profile`，
`POST /api/chat|turn-cube|dream`；WebSocket 发 `{"text": "...", "user": "..."}` 收回复。
默认只绑 `127.0.0.1`。

## 接 PyBot

```python

```

本机已有原版仓库（2026-11 实测可用，commit 7d63c7f）：

```

```

桥接查找顺序：`OMEGA_PYBOT_PATH` 环境变量 → 项目内 `vendor/pybot` → 上面这个本机路径。
找到后直接运行即可，不用设 PYTHONPATH：

```bash
cd ~/Desktop/量子模拟/右脑
python3 -m omega_mind --persona feynman
```

卡片没命中时，英文闲聊/事实才走 PyBot（"tell me a joke"、"what is the capital of France"
都有真答案）；PyBot 只会英文，中文输入它会掉进 greeting 兜底，所以中文模式不调用它，
直接改用 `knowledge.py` 的内置事实。桥接完全失败也不中断对话。
**不要**用 `python -m pybot -p` 子进程方式：每条消息都会重置记忆。
桥接把输入截到 2000 字——PyBot 有模块对超长输入做正则回溯，会卡住（实测踩过）。

## 费曼卡片检索（左脑第二来源）

优先使用 `~/Projects/feynman-open/knowledge/*.jsonl`（310 张卡：讲义卡、可教学单元、
物理护栏卡、光学/粒子/QED 等物理卡、生平/人格卡）。`feynman_kb.py` 用字符二元组 + TF-IDF 覆盖率打分，
纯标准库；命中要过三道门：查询覆盖率 ≥0.30，必须命中卡片的标题/标签/别名/不变量
（防止一个偶然的词把天气问题接到宇宙学卡上），而且一个由三个以上词组成的问句不能只靠
**一个**命中词拿分——「为什么彩虹总是七种颜色呢」不会因为面包车轶事的标签里有「颜色」、
或某个标题里有粘连 bigram「总是」就被答走；一问一主题的单 token 问句（"What is damping?"）
不受此限。评分只统计语料里存在的词，
标题词命中两个以上有少量加分；分数完全相同时，把这句问话原样列为别名的卡排前面
（"what is polarization" 不再因为文件顺序落到真空极化卡上），它只破平局、不抬分；
中文查询会按意图补同义词（如"浮在水上"→"浮力 漂浮"），
避免措辞差异直接漏检。宁可回答"这个我没把握"也不瞎接。

还有三条拒答护栏：英文闲聊（"tell me a joke"）、中英文个人经历问题（"我昨天吃了什么"）、
英文第三人称 why 问句（除非点名费曼）都不会去够卡片——这些属于记忆层或对话层，不是知识题。
`lookup()` 同时返回 `score`、`margin`（与第二候选的差距）和 `considered`，
供上层判断"是不是勉强接上的"。

**金标回归集**（`tests/test_retrieval_quality.py`）固定了 65 个正例（中英混合，允许一到两个
等价卡）和 10 个必须拒答的陷阱（记忆、闲聊、语料确实没有的题）；改权重或换语料时，
先跑它。标准是"费曼会不会"，不是"语料恰好有没有"——彩虹、天空、折射这类费曼主讲的内容
属于核心，缺卡就要补卡，不能靠拒答掩盖。

查找顺序：`OMEGA_KB_PATH` → `~/Projects/feynman-open/knowledge`。

回答顺序按语言分开：中文模式是「调用方给的 base_reply → 中文卡片 → 内置 10 条事实 → 兜底句」；
英文模式是「调用方给的 base_reply → 英文译文卡片 → PyBot → 英文内置库 → 兜底句」。
英文译文层按 `id` 覆盖回复字段，中文卡仍是事实源；它只是翻译，不是费曼原话。

右脑状态会改变左脑怎么找、说多少：压力/防御升高时提高检索门槛、偏好护栏卡、只说话最短的核心句；
好奇/多巴胺高时略降门槛、给可教学单元和方法卡加权、把卡片里的自检和边界也说出来；
精力低时候选只留一个、答案压到最短。策略只影响检索门槛、排序偏置和字段选择，不生成新事实；
本轮策略会出现在 `result.left_brain`、`/api/state` 和 `/api/chat` 回复里。

## 教回挑战（`/challenge`）

从 4 个可教学单元里出题（目前：线性松弛、守恒/源汇、反馈、阻尼），中英文各一套，用户用自己的话回答：

- 中文评分 = 0.6×不变量字符覆盖 + 0.4×关键术语覆盖；英文评分 = 关键术语覆盖率，
  术语匹配容忍词干差异（deviation / deviates）；两边都只在出现真实数量（小数或多位数）时乘数字命中系数；
- 中文 `strong`（≥0.5）/ `partial`（≥0.28）/ `weak`；英文 `strong`（≥0.55）/ `partial`（≥0.3）/ `weak`；
- 两次没答上来就公布 `force_invariant` 换下一题；
- 答错不加皮质醇，只加少量多巴胺——对费曼来说，"你愿意想"本身值得高兴。

挑战进度由引擎持有（`engine.challenge()`），CLI、HTTP 和存档共用同一个会话：

- `GET /api/challenge` 返回 `{available, active, question, tries, done, total}`；
- `POST /api/challenge` 支持 `{"action":"start"}` 与 `{"action":"answer","answer":"…"}`，
  返回判定、分数、反馈、命中/缺失术语；答完一题自动带下一题的 `next_question`；
  没有可教学单元时返回 503；
- 存档带 `challenge` 字段，重启后恢复到同一题、同一尝试次数；切换语言时进度指针跟着迁移；
- 仪表盘的「挑战」按钮走同一套 API。

## 空闲时间与存档

- CLI 读输入时用 `select` 每 5 秒让出一次：到点做梦、满足条件主动搭话，提示符照常可用。
- `--serve` 起一个后台线程，每 30 秒做一次 `maintenance()`（到点做梦）和 `tick()`（主动搭话），
  有输出才存档。服务器不再需要有人发请求才“活着”。
- 存档里包含语言模式、三层记忆、关系图、魔方布局、梦境、共振残余能量、挑战进度和
  **PyBot 自己的 memory**；PyBot 记忆里如果有不能 JSON 化的对象，会整体丢弃并标记，
  不至于把存档弄坏。
- 内存里的事件日志只保留最近 200 条（`MindEngine.EVENT_LOG_LIMIT`），长时间挂着也让内存有界；
  从存档恢复时同样按这个上限截断；存档里只写最后 50 条。
- 存档写成紧凑 JSON（每轮都写，不缩进），并用临时文件 + `os.replace` 原子替换；
  存档损坏或不是 JSON 对象时，`MindEngine.load()` 不抛异常，而是把原文件复制为
  `<原文件名>.corrupt`，从空状态启动，并把原因记在 `engine.load_warning`（CLI 会打印）。

## 记忆、睡眠、关系图与魔方

- **三层记忆**（`memory.py`）：working 最近 16 轮、episodic 最多 500 条并按显著性淘汰
  （未做梦的不淘汰）、semantic 用固定模式抽事实（名字/喜好/住址/工作），每条都带来源轮次和原句。
  中文和英文各有一套抽取模式：英文识别 `my name is`、`I live in`、`I love/hate`、`I work at`
  这类句式，值在第一个逗号/句号/从句处截断，`I love it` 这种指代不会当成事实；
  两种语言建的键相同（`kind:user`），换语言不会丢已有事实。
- **做梦**（`dream.py`）：未整理片段按权重攒到 8 就触发——普通一轮算 1，没答上的算 2.5，
  被用户纠正的一轮算 3.5，所以同一个问题连碰两次当晚就会复盘；按显著性和时间取前几条，
  主题来自 cubie 标签，叙述只引用用户原话「」；同时把事实推进语义记忆、把皮质醇/防御/唤醒往基线
  收 45%、加一点多巴胺。引擎 `tick()` 到点自动做梦，`/dream` 可手动强制。
- **梦后复盘**（`reflect.py`）：把没答上、勉强答、追问被纠正的片段记进 `reflect_history.json`，
  同一问题重复出现才铸缺口卡或修别名；上下文桥接（上一轮答对、这一轮追问没答上）和用户明确纠正
  首次出现即写入，但纠正卡标成 `user_claim`、boost 0.8，且任何写入前都要通过 golden 回归网；
  cortisol > 0.40 时只记录不改。删掉 `data/kb_learned/` 即可整体回滚。
- **扩散检索**（`spreading.py`，默认关）：文档共现图上按 NPMI 取邻居，给题目命中区再加 0.35 的
  邻接能量；精度门要求查询词命中卡的 title/tags/aliases，body 单独命中不许被抬分。实测会改变
  「熵是什么」「中微子是什么」的排序，所以只在 `OMEGA_SPREADING=1` 时启用，并仍受 golden 网约束。
- **关系图**（`relations.py`）：节点是人（`self` 是本体），边带类型和权重；亲密度按用户分开存，
  换人说话不会把上一个人的亲近带过去；"我妈妈叫王芳"这类句子会建关系边，只认带名字的。
- **魔方**（`cube.py`）：真的 3×3×3，26 块，六个面都能转（U/D/L/R/F/B，支持 `'` 和 `2`），
  每转一次记录历史（`R'` 存成 `R'`，可解析回放）；某个激活够强时自动把对应的面转 90°。
  `render_net()` 画十字展开图。
- **魔方回馈**（`cube_feedback.py`）：魔方不再是只写日志，而是有一条有界回边——
  被移到正面的方块在后续几轮评估里增益最多 +20%，久留则疲劳回落到 0.90；
  乱度越高，皮质醇的回归基线最多抬高 0.12、多巴胺最多压低 0.06（防御不设慢性残余）；
  正面角块会微调左脑候选数和回答详略（压力下仍以 `brief` 为准）；
  转动门控带滞回（已在正面需 0.83）和冷却（2 轮），并由原始强度下限 0.62 挡住"增益放大噪音"；
  做梦时沿自身历史的逆序走回约 45% 的错位。只有"离位"才算数，出生摆位不构成偏置。
- **联想边**（`assoc.py`，默认出声）：卡片之间存带类型的边——同机制、前提-结论、边界（"别和它混了"）、
  同域；人工确认的边各带一句机制和一句最强差异，引擎回答卡片题时自动在答案后追加
  最多一句（brief 略过），且绝不改变命中的卡和分数。中英是两条平行分支：每条边各写中英文
  两句（英文不从中文回译），中文交互只取中文句、英文只取英文句，对方卡没有英文名就整句不说，
  任何一边都不拿另一边兜底。机器挖出的候选边（`scripts/mine_assoc.py`，`origin=cooccur`）
  存在石墨里只供审查，永远不会被说出来：被点亮只是注意力，不是证据；人工审过的候选记在
  `scripts/data/assoc_review.json`。
- **语料画像**（`profiler.py`）：逐文件统计行数、类型、缺失字段、重复 id、验证状态、语言和长度分布，
  只读 JSONL。

## 已知边界

- 卡片语料 310 张、4 个可教学单元，覆盖不到的问题会明确说没把握；
- 检索靠二元组，同一概念换个说法可能漏检（"什么是熵"能中，"熵是什么"能中，中间夹字可能不行）；
- 内置知识只有 10 条（含中文问候和记名字），是最后一层兜底。
- PyBot 只会英文，所以中文模式完全不调用它；英文模式先用译文卡片，卡片没命中才落到 PyBot，
  这时回答质量取决于 PyBot 的模块匹配（比如 "heat" 会被辣椒模块抢答），这是 PyBot 本身的
  关键词匹配问题，不在本层修。
- 英文卡片是 217 条机翻覆盖层，不是费曼原话；`verified_facts` 里本来就是英文的 9 条保持原样，
  不做中文回译。覆盖层有 id 对齐、字段、无中文泄漏的自动化检查，但没有逐条人工语义校对；
  要引用原话，只用 `verified_facts` 或原始英文片段。
- 英文检索对“我/你记不记得昨天”这类个人记忆问题直接弃答，避免把传记里的 "remembered"
  当成记忆知识；一般性的 memory 问题只接受主题字段里真有 memory 的卡片。
- 服务器没有鉴权，只适合本机；要对外必须自己加反向代理和认证。
- 关系图只从"我X叫/是Y"这类明确句式建人；含糊称呼不建节点。
- 渲染器只做句式外壳；不生成新事实，也不做语义改写。
